# FUN&SUN Travel Mini App

Telegram Mini App для поиска, выбора и бронирования туров FUN&SUN.

## Запуск

```bash
cd fs-search-mini-app
npm run dev
npm run build
```

## Структура `src/`

| Путь | Роль |
|---|---|
| `views/` | Экраны: поиск, выдача, отель, авторизация, оплата |
| `components/` | Форма, фильтры, карточки туров/номеров, туристы |
| `stores/` | Pinia: параметры поиска, фильтры, туры, детали отеля |
| `api/` | Клиенты и моки Fun&Sun |
| `composables/useTelegram.ts` | Тема, кнопки, haptic, алерты |
| `types/` | Модели туров и отелей |

## ИИ в Mini App: зачем и куда встраивать

ИИ здесь не «чат ради чата», а слой поверх уже существующих сторов. Модель не бронирует сама: она заполняет `search` / `filters` / подсказывает отель, а бронь идёт тем же путём, что сейчас (`Auth` → `Payment`).

Все запросы к модели лучше делать **с бэкенда** (`fs-search-bot`), а не из Vue: ключ не светится в бандле, проще логировать и резать лимиты.

Ниже — варианты, которые стыкуются с текущими экранами.

### 1. Поиск на естественном языке

**Где:** поле над формой на `HomePage`, или сообщение боту до открытия Mini App.

Пользователь пишет фразу, модель возвращает JSON под `useSearchStore` — форма заполняется, человек жмёт «Найти».

Пример входа:

```text
Хотим в Турцию из Москвы в середине июня, 7 ночей, двое взрослых и ребёнок 5 лет, all inclusive, не дороже 180 тысяч
```

Пример ответа модели:

```json
{
  "from": "Москва",
  "to": "Турция",
  "date": "2026-06-14",
  "endDate": "2026-06-17",
  "nights": 7,
  "adults": 2,
  "childrenAges": ["5"],
  "filters": {
    "meals": ["AI", "UAI"],
    "priceMax": 180000
  },
  "clarification": null
}
```

Если даты или город неоднозначны — модель не угадывает, а спрашивает:

```json
{
  "filters": {},
  "clarification": "Из какого города вылет: Москва или Санкт-Петербург?"
}
```

Дальше `setSearchParams(...)` и переход на `/results`.

### 2. Умные фильтры на выдаче

**Где:** чип «Сказать, что важно» на `ResultsPage` рядом с `SearchFilters`.

Сейчас фильтры — десятки чекбоксов (звёзды, море, для детей). Модель переводит фразу в те же id, что ждёт `useFiltersStore`.

Пример:

```text
5 звёзд, песчаный пляж, анимация для детей, без вечеринок
```

```json
{
  "stars": [5],
  "beach": ["sand"],
  "forKids": ["animation"],
  "additionally": ["quiet"]
}
```

Несуществующие опции отбрасываются. Пользователь видит включённые чипы и может снять лишнее.

### 3. Персональные рекомендации отелей

**Где:** блок «Похоже, вам подойдёт» над списком на `/results`, сортировка вместо слепого `recommendations_FS`.

На вход: параметры поиска, 10–20 карточек из мока/API (название, звёзды, цена, питание, рейтинг, теги), короткий профиль (семья / пара / бюджет).

На выход — ранжирование и одна фраза «почему».

```json
{
  "rankedHotelIds": [1042, 881, 210],
  "reasons": {
    "1042": "5★, UAI, высокий рейтинг еды, цена в вашем диапазоне",
    "881": "Ближе к морю, чуть дешевле, 4★"
  }
}
```

Карточки те же `TourCard.vue`, меняется только порядок. Модель не выдумывает отели вне выдачи.

### 4. Вопрос-ответ по отелю (RAG)

**Где:** чат на `TourDetailsPage` («Можно с собакой?», «До пляжа далеко?»).

Контекст: описание отеля, номера, питание, фильтры из `tourDetails` / `hotel-details`. Модель отвечает **только** по этому тексту. Если в карточке нет факта — честный отказ, без выдуманного «да, можно».

Пример:

```text
Система: ты консультант FUN&SUN. Отвечай по JSON отеля. Если данных нет — так и скажи.
Отель: { "name": "FUN&SUN Smart", "beachDistanceM": 50, "pets": false, "meal": ["UAI"] }
Пользователь: Можно с йорком?

Ответ: В карточке отеля размещение с животными не указано / запрещено. Уточните у менеджера перед бронью.
```

Это снимает однотипные вопросы на экране номера, не подменяя оферту.

### 5. Сравнение 2–3 туров

**Где:** «Сравнить» на выдаче, если пользователь отметил несколько `TourCard`.

Модель получает одинаковые поля (цена, ночи, питание, звёзды, рейтинг, расстояние до моря) и пишет короткую таблицу плюс вывод «для семьи с ребёнком 5 лет лучше A, потому что…».

Пример вывода в UI:

| | A Smart | B Grand |
|---|---|---|
| Цена | 142 000 ₽ | 168 000 ₽ |
| Питание | UAI | AI |
| До моря | 50 м | 400 м |
| Вывод | A дешевле и ближе к пляжу; B — выше категория номеров |

Сравнение только по полям из API, без выдуманных SPA и «лучшего вида».

### 6. Помощник в Telegram-боте (до Mini App)

**Где:** `Bot_Function.cs` сейчас отвечает только на `/start`. Сюда логично поставить диалог.

Пользователь в чате: «Ищи Египет на май, двое». Бэкенд зовёт LLM, собирает `startapp`-параметры, открывает Mini App уже с заполненной формой:

```
/?from=274286&to=18803&date=2026-05-01&nights=7&adults=2
```

На `HomePage` эти query читаются в `searchStore`. Человек в Mini App только подтверждает и смотрит выдачу.

Имеет смысл, когда не хочется тыкать селекты большим пальцем в WebView.

### 7. Черновик данных туристов

**Где:** `TouristForm.vue` на оплате. Не автозаполнение паспорта «из воздуха».

Варианты с явным согласием:

- разобрать **вставленный** текст: `ИВАНОВ ИВАН ИВАНОВИЧ 01.02.1990 4515 123456`
- подсказать, какого документа не хватает (загран vs свидетельство для ребёнка 5 лет)

```json
{
  "lastName": "ИВАНОВ",
  "firstName": "ИВАН",
  "middleName": "ИВАНОВИЧ",
  "birthDay": "1990-02-01",
  "document": { "type": "passport", "series": "4515", "number": "123456" }
}
```

Поля всё равно показываются и редактируются. ИИ не отправляет бронь сам.

### 8. Голос → поиск

**Где:** иконка микрофона на главной. Telegram даёт голосовые; на бэкенде speech-to-text, затем тот же пайплайн, что в п. 1.

Нужно для сценария «иду / за рулём, руками не удобно». После распознавания пользователь видит текст и JSON-параметры и подтверждает.
